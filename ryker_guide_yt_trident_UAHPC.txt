##############################RYKER'S GUIDE TO INSTALLING ON CUSTOM YT/TRIDENT ON UAHPC####################################################################

UAHPC yt/Trident Installation Instructions
These instructions assume you already have an account for UAHPC and the VPN if needed.
First, go ahead and download the custom yt/trident files and extract them from the zip file. We won't need them for a while, but it's better to get them downloading in the background.

Open up two terminals. One will be used to connect to UAHPC, while the other will be used to manipulate files on your end.

On the connection terminal, use the command "ssh {username}@uahpc.ua.edu" substituting {username} for your myBama username. If this is your first time connecting on this computer, it'll ask about adding the key to known hosts. Go ahead and accept that, input your password as needed, and do whichever two-factor authentication method is best for you.

Now you're connected to the head node. Normally, I would run through the process of going into a computation node, but something seems to be up with that, so that's for later. Now run "module load python/python3/3.11.6" to activate python. From here, you can run "pip install trident" and "pip install yt==4.2.2" which should work normally. If either of those run into errors, run "module load cmake/3.26.3_gcc_11.1.0" and run the command again after adding "--no-binary" right after the word install.

Once those are installed, run python and import Trident. It'll ask about ion tables, and all of the default values are perfectly fine. If you want, you can also do the verification test that they ask about, but it likely isn't necessary. Try to import yt as well. If it returns a segmentation fault, uninstall yt and reinstall it following the instructions for errors in the previous paragraph. Next, run "yt.__file__" or "trident.__file__" and copy the path that is returned, excluding the "init.py" at the end of it. This is the path to the folder for yt or trident, which we'll need to have to move the custom files over.

Switch to the other console. Change directories using "cd {directory}" until you reach the location of the custom yt and Trident files you unzipped earlier. There are three folders of the custom files: one for yt, one for Trident, and one for config files. Pick a folder and see which files it contains. Make sure to cd into the folder in the console as you do so. If you picked the folder with yt files, you'll run into a folder named "yt" with a folder named "frontends" inside, and two folders inside that one named "arepo" and "gadget." Enter the "arepo" folder, where you should see "data_structures.py". In the console, use the command "scp data_structures.py {username}@uahpc.ua.edu:{path to yt files}/frontends/arepo/" replacing {} entries with your username and what was copied earlier, respectively. Make sure there are no double slashes before running! When it asks for a two-factor authentication method, it won't show which response you're picking, because it's treating it like a password field. If everything goes smoothly, use "cd .." to back out of the arepo folder, then use "cd gadget" followed by "scp io.py {username}@uahpc.ua.edu:{path to yt files}/frontends/gadget/". Then use "cd .." until you've exited this folder of the custom files and pick a new one.

If you picked the trident folder, use the command "scp -r ./trident/ {username}@uahpc.ua.edu:{path to trident files}". If your console is outside the custom trident folder, you'll need to remove the "/trident/" from the path to the trident files. 

If you picked the config folder, use the command "scp {filename} {username}@uahpc.ua.edu:~/" for both of the files inside.

Go ahead and switch back to the connection terminal, then run "ls". You should see the config files in the output. From here, your installation should be complete! I recommend copying over the test script and its requisite cutout files using the same process for the config files. The test script also requires a folder called "TestRays" or something along those lines, which you'll need to make using "mkdir TestRays". You can run the test script on the head node, but limit it to doing one or two rays only, just to be polite. If you want to run it at full strength, use "srun --pty -p main -q main /bin/bash" (although this was not working for Deon last time we tried) to enter a computation node, where you can run things freely.
